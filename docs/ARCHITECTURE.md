# Architecture — BBC English Academy (full-stack)

```
┌─────────────────────┐     HTTPS / JSON      ┌──────────────────────────┐
│  Cloudflare Pages   │ ─────────────────────▶ │  Render Web Service      │
│  frontend/ (static  │  API_BASE_URL env     │  backend/ (Node+Express)  │
│  HTML/CSS/JS, EN/AR)│                       │  JWT auth, roles,        │
└─────────────────────┘                       │  validation, rate limits │
                                              └────────────┬─────────────┘
                                                           │ DATABASE_URL
                                              ┌────────────▼─────────────┐
                                              │  Supabase PostgreSQL     │
                                              │  db/migrations/*.sql     │
                                              │  + RLS policies          │
                                              └──────────────────────────┘
```

## Frontend (`frontend/`)

- Vanilla HTML/CSS/JS, no framework, no build step for local use. One
  `styles.css` + `app.js` shared by all pages; `config.js` holds the API base
  URL (generated by `build.js` from `API_BASE_URL` on Cloudflare Pages).
- `API_BASE_URL` empty = **demo mode**: pages render the demo catalogue in
  `app.js`, and a yellow DEMO MODE banner is shown. No data leaves the device.
- Language: EN/AR toggle flips `dir` (LTR/RTL) and persists in `localStorage`.
  Auth token in `localStorage` (`bbc-token`); user in `bbc-user`.
- Light by design: no photos, no 3D, no webfonts, system fonts only — pages
  stay usable on 2G/3G. Live classes are a **link field** on a lesson
  (`live_class_url`, e.g. a Zoom/Meet link supplied by the teacher); no video
  platform is built into this codebase.

## Backend (`backend/`)

- Node 20 + Express. `src/server.js` = routes + auth + validation;
  `src/db.js` = data layer with two implementations of one interface:
  - `PgStore` (used when `DATABASE_URL` is set): real PostgreSQL queries
    against the `db/migrations/` schema.
  - `MemoryStore` (default): in-memory demo data, lost on restart. For local
    smoke tests only — never production.
- Auth: bcryptjs password hashing (never plaintext), JWT (7 days default),
  roles `student` / `teacher` / `admin` enforced per route. Rate limiting on
  `/api/auth/*` (100 req / 15 min). CORS restricted to `CORS_ORIGIN` list.
- Input validation is hand-written per route (required strings, email format,
  password ≥ 8 chars, grade 0–100, placement answers exactly 20 indexes).
- Placement test: 20 questions. The frontend scores instantly for feedback;
  the backend re-scores from the submitted answer array and stores the
  result — the frontend's answer key is not trusted for the stored record.

## Database (`db/`)

- `migrations/001_init.sql`: tables `profiles`, `roles`, `courses`, `levels`,
  `lessons`, `enrolments`, `placement_tests`, `placement_results`,
  `assignments`, `submissions`, `grades`, `attendance`, `announcements`,
  `payments`, with FKs, indexes and CHECKs.
- `migrations/002_rls.sql`: Row Level Security — students see own rows,
  teachers see their courses' rows, admins see all.
- `migrations/003_storage.sql`: `avatars` (public) and `materials`
  (authenticated) Storage buckets.
- `supabase/seed.sql`: demo levels/courses/lessons/announcement only.
  Prices are NULL on purpose; teacher seed rows are labelled DEMO with a
  placeholder hash (create real users via the API instead).

## What is NOT built here (by design)

- No real payment provider, no card handling, no money flow — `payments`
  records a placeholder intent/status only.
- No email sending — email is a placeholder (a real provider, e.g. Resend /
  Supabase Auth emails, is a TODO).
- No video conferencing, no file uploads to Storage from the API yet
  (buckets exist; upload wiring is a TODO).
- No certificate generation/verification page yet (TODO, see root README).
- No BBC (British Broadcasting Corporation) branding, logos or affiliation.

## Security notes

- Change `JWT_SECRET` in production; never commit `.env`.
- The in-memory store must never be used with real student data.
- Admin self-registration is blocked unless `ADMIN_SETUP_KEY` is set and
  supplied in header `x-admin-setup-key`.
- RLS protects direct Supabase access; the API additionally enforces roles
  in code, because it connects with a service-style connection string.
